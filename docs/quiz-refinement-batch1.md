# Spontaneous quizzes and question quality — sandbox report

Date: 19 October 2026. Branch: `quiz-grounding-refinement`, based on deployed commit `c341cfc`. No deployment performed.

## Scope and result

Implemented spontaneous Mini App quiz generation and source-grounded question-quality improvements. The existing scheduled quiz path remains covered by regression tests. Complex combined requests and the experimental coordinator are excluded; neither was imported from the older experimental worktree. General response cleanup and Mini App UI refinement are outside this batch.

The ordinary owner and nonowner quiz flows passed the final synthetic real-model experiments. One strict negative-topic constraint remains unreliable, described below. These results establish tested prototype functionality, not a guarantee of semantic correctness for every generated question.

## Root causes addressed

- A saved quiz job could be followed by further model calls, repeated reads, or failure despite successful preparation. A verified saved-job receipt now ends that quiz turn and directs the user to Generated Practice in the Mini App. A study schedule is unnecessary.
- Follow-up requests could lose the actual learning sources behind the preceding explanation. Recent verified source handles are recovered only within the same actor and conversation generation; assistant prose is not silently converted into learning material.
- Source identifiers and quotations were being regenerated by the model. Python now assigns passage handles to actual source spans and binds selected handles back to their original text and actor-owned source revision. The model selects relevant evidence rather than copying UUIDs or inventing provenance.
- Assessment scope and learning content were insufficiently separated. A quiz-specific source-selection step interprets the original student request, distinguishes concept practice from assessment preparation, and separates assessment scope from the learning passages supplied to the question writer.
- Question generation now receives the original request, source passages, application/scenario guidance and private review. Review covers unsupported claims, scope, weak or repetitive questions, answers and explanations. One bounded correction is permitted; repeated defects or uncertain inference fail without publishing a partial set.
- Display choices are shuffled together with their private key and explanations. Explanations referencing display letters are rejected before publication because labels are assigned after generation. Answer keys remain private until submission through the existing API.
- Known returned gateway tool-format rejections receive one bounded format correction. Unknown tools, authentication errors and uncertain transport failures are not blindly replayed. Server-added citation fields are kept out of model correction drafts.

Natural-language interpretation and passage relevance remain LLM decisions. There is no keyword router mapping course names or query phrases to quiz workflows. Code enforces actor ownership, source provenance, output structure, idempotency and publication boundaries.

## Remaining limitation

One final strict-focus run asked how carbon awareness differs from lowering electricity consumption, despite the request explicitly excluding energy-efficiency questions. Its evidence was real and source-grounded, but its scope was too broad. The same request passed on repetition. The LLM review did not reliably catch this distinction, so strict topic exclusions cannot yet be claimed reliable.

This is a semantic quality limitation, not an authorization bypass or a missing Mini App save. Provenance validation proves where evidence came from; it cannot by itself prove the model respected every topic constraint. A more reliable semantic scope gate would require further measured work, rather than silently adding a phrase-specific filter. Normal source-based practice is suitable to consider for prototype live testing, with this limitation disclosed; deployment still requires the user's decision.
